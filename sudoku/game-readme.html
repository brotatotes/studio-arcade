Sudoku

A two-color 9×9 Sudoku puzzle. One puzzle per seed; every generated puzzle has a unique solution.

Rules

  • Fill every cell so that each of the digits 1..9 appears exactly once in every row, every column, and every 3×3 box.
  • The puzzle starts with some cells already filled — these are the givens and cannot be changed.
  • You win when every empty cell is filled correctly (all 27 row/column/box constraints satisfied).

Visual conventions

  • Strict two-color palette: black ink on an off-white background.
  • Givens are rendered large and centered in their cell (scale-4 glyphs).
  • User-entered digits are rendered much smaller and positioned in the top-right corner of their cell (scale-2 glyphs, roughly half the size of givens). This makes givens vs. player entries unambiguously distinguishable from a screenshot.
  • Pencil marks (candidates) are tiny digits in a 3×3 sub-grid inside an empty cell.
  • Coordinate labels: rows labeled A..I down the left edge, columns labeled 1..9 across the top. These are orientation labels only, not playable cells.
  • 3×3 box boundaries are drawn with thick (3 px) lines; individual cell boundaries with thin (1 px) lines.
  • The selected cell shows a solid black cursor highlight; the digit in that cell (if any) is inverted to the off-white color.

Controls

  • Title screen: press any key to begin.
  • Arrow keys: move the cursor.
  • 1..9: enter a digit into the selected cell (or toggle a pencil mark in pencil mode).
  • P: toggle pencil-mark mode. A small filled square appears in the top-left while pencil mode is active.
  • 0 / Delete / Backspace: clear the selected cell.

Win condition

When the board is fully and correctly filled, a black-bordered off-white panel appears centered over the grid with the word SOLVED.

URL parameters

  • ?seed=N — integer seed for puzzle generation (default 1).

What's verified

  • Generator correctness & uniqueness — 1000-puzzle sample, 100% uniqueness on accepted puzzles, ≥40% acceptance rate.
  • Difficulty distribution — technique-tier classifier (naked/hidden singles → pointing/pairs → X-wing/triples → swordfish/XY-wing); bars ≥35/30/20/10% easy/medium/hard/expert; 100% no-guess at expert and below.
  • Solve correctness — 100 seeds played end-to-end (file://) and 10 seeds replayed over real HTTP serve; each reaches state.won === true.
  • Legibility — Bar B blind vision-judge over 5 seeds; judge restates rules, counts givens (±3), identifies row/col/box constraints, describes UI affordances. Pass ≥4/5.
  • Fuzz robustness — 200 puzzles × 10,000 random keypresses each (2,000,000 keys total); 0 pageerrors, 0 console errors, 0 state violations.
  • Performance — render-bar frame time and FPS sampled across 5 seeds; bar = 60 FPS / 16.7 ms.

What's NOT verified

  • Touch / mobile input. Keyboard-driven only; no pointer-tap or touch gesture support and no verifier coverage of mobile browsers.
  • Accessibility / screen readers. Pure canvas render — no DOM grid, no ARIA, no keyboard focus indicators outside the in-canvas cursor.
  • Cross-browser parity. Verifiers run under Chromium only (Playwright default). Firefox / WebKit not exercised.
  • Save state. Refreshing the page resets the puzzle. ?seed=N is the only state-restoration mechanism.
  • Real-time rule-violation feedback. Deliberately omitted (palette cleanliness); only checkWin fires on a fully-filled board.

Two-color palette · 16 KB bundle ceiling · no runtime dependencies.
